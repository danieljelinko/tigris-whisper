# 03 · Decisions

| Date | Title | Context | Decision | Consequences |
|---|---|---|---|---|
| 2026-05-29 | One launcher, swappable backend | Daemon only needs an OpenAI-shape `/v1/audio/transcriptions` HTTP endpoint; Docker dep lived only in launcher scripts | Add single `run.sh` that detects host and brings up a per-platform backend behind the same `WHISPER_API` | No client rewrite; backends are independent and individually testable |
| 2026-05-29 | Drop Docker on Mac | Docker on macOS can't reach the Apple-Silicon GPU → CPU-only in a RAM-heavy VM, bad on 8 GB | Mac uses native whisper.cpp + Metal, not Docker | Mac needs a native install path (brew/cmake) instead of `docker run` |
| 2026-05-29 | whisper.cpp = shared Linux+Mac artifact | Need to honor red/green TDD but dev box is Linux; Mac-specific runtimes can't be tested here | Linux-no-GPU backend uses whisper.cpp CPU — the *same* server Mac runs with Metal | Developing CPU backend here de-risks Mac to one build flag; mlx can't share this |
| 2026-05-29 | Keep Linux+NVIDIA on Docker | Existing CUDA container path is proven and in daily use | Leave it unchanged; `run.sh` routes Linux+GPU → Docker | No regression risk to the working path |
| 2026-05-29 | mlx-whisper deferred to Phase 2 | Fastest on Apple Silicon but `import mlx` fails on Linux and it ships no HTTP server | Evaluate on-device only; benchmark vs whisper.cpp on the real M1 before making it default | Phase 1 default stays whisper.cpp (safe drop-in); default revisited after benchmark |
| 2026-05-30 | Mac default model = mlx large-v3-turbo q4 | M1 8 GB is tight, and the non-quantized mlx model download is too large/slow for first-run smoke tests | `mlx-community/whisper-large-v3-turbo-q4`; disable HF Xet by default for predictable downloads | Comfortable default for Apple Silicon; can override with `WHISPER_MLX_MODEL` |
| 2026-05-30 | Ship a generated Mac `.app` wrapper first | Users should grant permissions to a named app, not Terminal/iTerm/VS Code; but a full Swift menu bar app would slow the current install-validation loop | Generate `~/Applications/tigris-whisper.app` with an `Info.plist` and launcher that runs the existing repo `run.sh` | Permissions can appear under **tigris-whisper** and the CLI remains source of truth. Future Swift/menu-bar/signing work can replace the wrapper without changing backend logic |
| 2026-05-30 | Provide a first-party uninstall script | The installer creates user-visible app/state/log files and mlx-whisper downloads large HuggingFace models lazily; users need a supported cleanup path | Add `uninstall.sh` plus `tests/test_install_uninstall.sh` for fake-mac install/uninstall behavior | Keep cache deletion scoped to known project model dirs by default; never wipe all HuggingFace or Pixi state unless the user opts in |
| 2026-05-30 | Rename to `tigris-whisper` only after repository coordination | The bootstrap one-liner depends on the GitHub slug; changing `REPO_SLUG` before the repo rename would break clean installs | After the GitHub repo was renamed, update the canonical slug, default install dir, app bundle name, bundle id, logs/state paths, docs, and tests together | Internal Python module filenames can remain until there is a technical reason to rename them |
| 2026-05-30 | Bootstrap warms the Mac model cache | Users were confused when first transcription appeared stuck; mlx downloads the model lazily, so the first real request can take several minutes | Run `scripts/test_mac_setup.sh` automatically from bootstrap on macOS unless `TIGRIS_SKIP_SMOKE_TEST=1`; final instructions make `tigris-whisper.app` the normal path and `./run.sh` manual/dev mode | Fresh installs take longer but fail earlier and visibly; model download happens during setup with progress messaging instead of during the first dictation |
| 2026-05-30 | Request Microphone at app startup | macOS Microphone settings may not list an app until it has requested the microphone; waiting for the first hotkey can block users because Accessibility may not be granted yet | Open a short `sounddevice.InputStream` during Mac daemon startup to trigger/list Microphone consent immediately | Launching the app should now surface the Microphone prompt before the user tries dictation |
| 2026-05-30 | Add CLI lifecycle controls before a menu bar app | Background apps need a stop/restart/status path even before full UI polish | Add `scripts/control_mac_app.sh status|start|stop|restart|logs` and make the wrapper track the child daemon PID | Users can recover from stuck/background runs; future menu bar UI can call the same control behavior |
| 2026-05-31 | Model choice belongs in bootstrap config | The right Whisper model depends on Mac RAM, language/noise, and latency tolerance; hard-coding one model makes M1 8 GB users wait even when they prefer speed | Bootstrap asks for a profile and writes `tigris-whisper.env`; `run.sh`, app launch, smoke test, install, and uninstall all honor `WHISPER_MLX_MODEL`; installer/docs identify the offered models as multilingual and link to OpenAI's language list | Default remains `mlx-community/whisper-large-v3-turbo-q4`; users can choose `small-mlx-q4`, `base-mlx-q4`, or full `large-v3-turbo` without editing source |
| 2026-05-31 | Mac paste should target the app where recording began | Starting/stopping/transcribing can move focus to Terminal, notifications, or the app wrapper; a blind Cmd+V may hit the wrong process or fail silently | Capture the frontmost process at recording start, restore it via System Events before Cmd+V, and log the full `osascript` error | Clipboard remains the fallback; missing Accessibility is now easier to diagnose from `~/whisper_hotkey_mac.log` |
| 2026-05-31 | Pre-download MLX models before server start | Lazy downloads inside the Flask transcription request hide Hugging Face progress behind a waiting curl request, making setup look stuck | Add a foreground `scripts/download_mlx_model.py` helper and call it from the MLX backend and Mac smoke test before starting the server | Terminal users see Hugging Face/tqdm progress bars; app launches still write progress to logs when no terminal is visible |
| 2026-06-08 | Benchmark harness is backend-agnostic via HTTP contract | All 5 backends share `POST /v1/audio/transcriptions` + `GET /` → `{model}` | Client targets an endpoint URL; backend identity and model are probed at runtime, not hard-coded | Same harness runs on Linux CPU, Linux CUDA, macOS without code changes |
| 2026-06-08 | Results are committed, not gitignored | Benchmark data is community evidence; gitignoring it means each runner re-generates it and no cross-hardware comparison is possible | Timestamp-named `benchmark/results/*.{json,md}` are tracked in git and pushed; audio WAVs are gitignored (large, user-generated) | README proof block auto-updates from committed JSON via `readme_snippet.py`; new contributor data accretes over time |
| 2026-06-08 | Default scoring keeps accents (é ≠ e) | Folding accents masks real diacritic errors, especially for HU/FR | `fold_accents=False` by default; `--fold-accents` flag for lenient mode | FR/HU WER is higher but honest; users can opt into leniency |
| 2026-05-31 | Model changes should not require reinstall | Users may want to try faster/smaller models after install; editing env files is unnecessary friction | Add `scripts/change_mlx_model.sh` to update `tigris-whisper.env` interactively or from profile/model arguments | Reinstall remains unnecessary; a running daemon still needs restart to use the new model |
| 2026-05-31 | Use an AppleScript applet for the Mac wrapper | LaunchServices can reject a `.app` whose `CFBundleExecutable` is just a shell script, surfacing `_LSOpenURLsWithCompletionHandler() failed with error -600` | Generate the app with built-in `osacompile` when available, and keep the shell logic as `Contents/Resources/launcher.sh` | No Xcode needed; LaunchServices gets a native app executable while our existing launcher behavior remains testable |
| 2026-05-31 | Install output should be remotely inspectable | Mac install debugging was requiring manual copy-paste from the user's Terminal | Tee `bootstrap.sh` and `install.sh` output to timestamped logs and stable `*-latest.log` symlinks under `~/Library/Logs/tigris-whisper` | SSH debugging can inspect the exact install output after the fact; users still see the same Terminal output |
| 2026-06-07 | faster-whisper replaces whisper.cpp CPU as Linux no-GPU default | whisper.cpp large-v3-turbo-q5_0 was too slow on CPU; faster-whisper with CTranslate2 int8 is 2-4× faster for the same model; no cmake build step needed (pure Python wheels); default model is `small` (~490 MB, good accuracy/speed trade-off); whisper.cpp stays available via `WHISPER_BACKEND=whispercpp_cpu` | Linux no-GPU installs are now faster to set up and faster to transcribe; model selection added at install time matching the Mac UX pattern |
| 2026-06-07 | faster-whisper is Linux-only; mlx-whisper remains Mac default | faster-whisper/CTranslate2 does not benefit from Apple Silicon GPU; mlx-whisper via Pixi wheels is already the best Mac option | No UX change on Mac; Linux gets the new backend |
| 2026-05-29 | Candidate future backends (Parakeet / Voxtral / Windows) | User asked what it'd take to add NVIDIA models, Voxtral, and Windows | Defer to Phase 3; all reuse the `/v1/audio/transcriptions` plug-in pattern. Parakeet-0.6B = best Linux+GPU upgrade; Voxtral only via **4-bit quant** on this 8 GB-VRAM box; Windows easiest under WSL2 | No commitment now; tracked in `01_plan.md` Phase 3. None address the Mac goal |
| 2026-05-29 | **Mac default switched to mlx-whisper** (was whisper.cpp Metal) | Wanted to avoid the ~1–2 GB Xcode CLT + Homebrew + binary-distribution burden. mlx-whisper installs as prebuilt wheels in a Pixi-managed env — no compiler, no brew, no binary to ship; model auto-downloads from HF | Darwin → `mlx`; whisper.cpp Metal kept as `WHISPER_BACKEND=whispercpp_metal` fallback | **Loses Linux-side TDD of the Mac transcription** (mlx is Apple-Silicon-only); we test the HTTP wrapper with a mocked boundary instead. `git clone` still pulls CLT on a fresh Mac, so bootstrap uses tarballs when git is unavailable |
