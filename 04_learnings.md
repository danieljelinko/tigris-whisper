# 04 · Learnings

| Date | Title | Non-obvious truth | Implication |
|---|---|---|---|
| 2026-05-29 | Docker can't use the M1 GPU | Docker Desktop on macOS runs a Linux VM with no passthrough to Apple Silicon GPU/ANE; `--gpus all` is NVIDIA-only | Containerized Whisper on Mac is always CPU-only — don't ship Docker as the Mac backend |
| 2026-05-29 | MLX is untestable on Linux | `mlx`/`mlx-whisper` require Apple Silicon; they won't import on this dev box | Any mlx work cannot be TDD'd here — it's strictly on-device (Phase 2) |
| 2026-05-29 | `WHISPER_API` is the whole contract | Client only POSTs a WAV and reads `{"text": ...}`; it neither knows nor cares about the backend | New backends just need to serve `/v1/audio/transcriptions` on :4444 — no client changes |
| 2026-05-29 | whisper.cpp server has an OpenAI-shape endpoint | `whisper-server --inference-path /v1/audio/transcriptions` is a drop-in for the existing client | Lets us reuse the exact same daemon + tests across Docker and whisper.cpp |
| 2026-05-29 | macOS paste needs Accessibility + Mic perms | Synthetic paste and mic capture both require TCC consent on first run; silent failure is possible when permissions are missing | Mac client setup must document granting Microphone + Accessibility or paste/recording fails quietly |
| 2026-05-29 | This dev box GPU = 8 GB VRAM (RTX 5070 Laptop) | bf16 Voxtral-Mini-4B needs ≥16 GB; won't load here unquantized | A GPU LLM-ASR backend on this machine must be ≤~4-bit quantized; Parakeet-0.6B fits with room to spare |
| 2026-05-29 | Windows can keep the Docker+CUDA backend | Docker Desktop on Windows does NVIDIA CUDA passthrough via WSL2; `run.sh` (bash) runs as-is under WSL2 | Windows support is mostly a `backend_select` case + client paste tweak; native (no-WSL) needs a `run.ps1` port |
| 2026-05-29 | Parakeet/Canary have no native OpenAI endpoint | NeMo/Riva expose gRPC/their own HTTP, not `/v1/audio/transcriptions` | Adding them needs a ~30-line FastAPI wrapper to match the contract; Voxtral-via-vLLM does have it natively |
| 2026-05-29 | `curl \| bash` scripts can't `read` from stdin | When piped, fd 0 is the script text, not the keyboard — a plain `read` returns empty instantly | Read interactive prompts from `/dev/tty` (with a default fallback when no tty); `bootstrap.sh` does this for the install-dir prompt |
| 2026-05-29 | Xcode CLT is a hard prereq even with Homebrew | The ~1–2 GB CLT package provides clang, ld, make, git, and the macOS SDK headers that whisper.cpp's compile/link step needs | `bootstrap.sh`/`install.sh` must trigger `xcode-select --install` and wait for it before brew/build steps |
| 2026-05-29 | `brew install whisper-cpp` ships a prebuilt bottle | The slow 1–2 GB on Mac was never whisper.cpp compiling — it's Xcode CLT, which Homebrew mandates as a baseline | To truly drop the big download, drop Homebrew: the mlx path uses Pixi + wheels. `git clone` still triggers CLT though (use a tarball download to avoid even that) |
| 2026-05-29 | mlx-whisper downloads lazily | `mlx_whisper.transcribe(path_or_hf_repo=...)` fetches weights from HuggingFace to `~/.cache/huggingface` on first transcription | Bootstrap should pre-warm by running `scripts/test_mac_setup.sh`; direct `./install.sh` users can run that test manually |
| 2026-05-29 | Keep the mlx import lazy for cross-platform testing | `import mlx_whisper` at module top would break collection of `test_mlx_server.py` on Linux | `mlx_whisper_server.py` imports mlx *inside* `transcribe_audio`; the Flask contract test monkeypatches that function and runs anywhere |
| 2026-05-29 | GitHub auto-serves repo tarballs; curl avoids Xcode CLT | `github.com/<slug>/archive/refs/heads/<ref>.tar.gz` is generated on demand (nothing to host); `curl`+`tar` are built into macOS, unlike `git` | `bootstrap.sh` falls back to a tarball when git is absent → full install with zero Xcode CLT. `tar --strip-components=1` drops GitHub's top-level dir |
| 2026-05-30 | A `.app` wrapper improves TCC identity but does not remove permissions | macOS still requires Microphone and Accessibility consent; wrapping the launcher only changes the visible app identity users grant | Generate `tigris-whisper.app` so permissions attach to a named product where possible, and keep docs explicit that users still grant both permissions |
| 2026-05-30 | Avoid `pyautogui` on macOS | Launching from a `.app` exposed a `rubicon.objc` crash while importing `pyautogui`; native `pbcopy` + `osascript` are enough for clipboard/paste | Mac daemon uses built-in macOS tools for paste and keeps Accessibility as the only paste permission requirement |
| 2026-05-30 | Uninstall must distinguish project cache from shared tools | The mlx model is large and project-owned, but Pixi and HuggingFace cache roots may be shared by other projects | Delete known model cache dirs by default; make install-dir and Pixi removal explicit/confirmed |
| 2026-05-30 | First-run model download should be setup work | If the first model download happens during the user's first dictation, the app looks stuck even though it is working | Bootstrap now runs the smoke test/model warmup automatically and says explicitly that the selected model download can take several minutes |
| 2026-05-30 | Microphone settings are request-driven | macOS may not list the app under Microphone until the app has requested input access | The Mac daemon must request the microphone at startup, otherwise users can stare at an empty Microphone list before the hotkey path ever runs |
| 2026-05-31 | Clipboard success does not prove paste permission | `pbcopy` can write the clipboard without Accessibility, while AppleScript/System Events Cmd+V still needs Accessibility for the launching app identity | If transcript is copied but not pasted, grant Accessibility to `tigris-whisper` for app mode or the terminal app for `./run.sh`; keep the text in clipboard as a manual fallback |
| 2026-05-31 | MLX Whisper model IDs are runtime config | `mlx_whisper.transcribe(..., path_or_hf_repo=...)` accepts HF repo IDs and downloads them lazily; MLX Community publishes q4/fp32/full variants | Persist `WHISPER_MLX_MODEL` in `tigris-whisper.env` so bootstrap, app, tests, and uninstall agree on the selected model/cache |
| 2026-05-31 | Offered bootstrap models are multilingual | Whisper has separate English-only variants for tiny/base/small/medium, but the selected tigris-whisper bootstrap models are multilingual variants | Show "multilingual" beside each model choice and link users to OpenAI's language token list; warn that accuracy still varies by language |
| 2026-05-31 | Lazy model downloads hide progress | When the first download happens inside a background server request, the user only sees the waiting client, not Hugging Face's progress UI | Download the selected model in a foreground setup step before starting the server so Hugging Face/tqdm progress can render normally |
| 2026-05-31 | Pynput's trusted-process warning is Accessibility | `This process is not trusted! Input event monitoring will not be possible` means macOS TCC has not granted Accessibility to the process running the daemon | Check `AXIsProcessTrusted()` at startup and tell users to grant the terminal app for `./run.sh` or `tigris-whisper` for app launches, then restart |
| 2026-05-31 | Changing models is just config | The MLX server reads `WHISPER_MLX_MODEL`; no install-time dependency changes are needed for another HF Whisper repo ID | Provide a picker script that rewrites `tigris-whisper.env`; restart the daemon/app so the new environment is read |
| 2026-05-31 | Real sample transcription is useful but slow | The Mac smoke test's sample WAV proves the full HTTP→mlx→JSON path, but first MLX inference can take over a minute due to initialization/compile | Make the check explicit, bounded by `TIGRIS_TRANSCRIPTION_TIMEOUT`, and skippable with `TIGRIS_SKIP_TRANSCRIPTION_TEST=1` |
| 2026-05-31 | LaunchServices dislikes shell-only app executables | A hand-written `.app` with a shell script as `CFBundleExecutable` can fail with `_LSOpenURLsWithCompletionHandler() failed with error -600` | Use `osacompile` to generate a native AppleScript applet and have it launch the shell helper in `Contents/Resources` |
| 2026-05-31 | Install logs are better than screenshots | Remote debugging a Mac install from SSH is painful when the only copy of stdout is in the local Terminal scrollback | Tee bootstrap/install output to stable log paths under `~/Library/Logs/tigris-whisper` |
| 2026-05-31 | `osacompile -o app` wants to create the bundle | Pre-creating the `.app` directory before `osacompile -o` can fail with `errOSASystemError (-1750)` | Remove the old app, let `osacompile` create the bundle, then add/overwrite our `Info.plist`, `repo_path`, and launcher helper |
| 2026-06-25 | mlx-audio is the multi-family Mac STT library | `from mlx_audio.stt import load; load(model_id).generate(path).text` serves Whisper/Nemotron/Omnilingual/Cohere/Parakeet from one API, model picked by id | One `mlx_audio` backend covers every new Mac model; keep the import lazy (inside `get_model`) so the Flask wrapper imports/tests on Linux with the boundary mocked |
| 2026-06-25 | `model_catalog.py` must stay stdlib-only | `change_model.sh` calls it via real `python3` (not pixi/uv) so the picker works under the install test's fake-pixi shim and on machines before the venv exists | Don't add heavy imports to `model_catalog`/`backend_select`; if resolution ever needs a dep, route it through a separate module |
| 2026-06-25 | New-model HF ids checked against the live Hub | Hub-existence (not on-device load) verified 2026-06-25: `nemotron-3.5-asr-streaming-0.6b` resolves; `cohere-transcribe-03-2026` does **not** — the published MLX repo is `cohere-transcribe-03-2026-mlx-8bit`; no `mlx-community/omniASR-*` MLX repo exists at all (only `facebook/*` PyTorch). Catalog now: Cohere id fixed, all 4 Omnilingual `darwin` placements `None`. **mlx-audio load+transcribe still unconfirmed (Linux box, no Apple Silicon)** — run step-1 on the Air to close it | Mac picker offers Whisper + Nemotron + Cohere (not Omnilingual until an MLX build ships); restore an Omnilingual `darwin` placement when one appears |
| 2026-06-25 | HF model-API returns 401, not 404, for missing public repos | `GET huggingface.co/api/models/<id>` answers 401 for a non-existent (or private) repo and 200 for a public one — a fake control id also 401s | Treat 200 = resolves, 401 = does-not-resolve when scripting Hub existence checks; don't wait for 404 |
| 2026-06-25 | The Mac picker needs a non-stub python3 pre-install | `bootstrap.sh choose_mac_model` resolves the catalog via `python3` before `install.sh` runs, but a CLT-less Mac's `/usr/bin/python3` is an Xcode stub that pops the install dialog (like `/usr/bin/git`) | Picker skips `/usr/bin/python3` on Darwin and falls back to the static Whisper default when no usable python3 exists yet, so a fresh tarball install never triggers CLT; new families appear once pixi's python is present |
| 2026-06-25 | Catalog/test invariants guard data drift | `test_model_catalog.py` asserts every placement's env var matches its backend and every referenced backend is declared in `backend_select.BACKENDS` | Adding a model/backend with a typo'd env var or undeclared backend fails fast in CI, not at runtime on a user's Mac |
| 2026-06-25 | Unpinned transitive numba backtracks to an unbuildable sdist | mlx-whisper declares `numba`/`numpy` unconstrained; numpy floats to 2.5.0, every modern numba caps numpy below that, so pixi/uv backtracks the *unpinned* numba to 0.53.1 (loose metadata) instead of capping numpy — and 0.53.1 has no osx-arm64/py3.12 wheel, so its sdist build fails (`versioneer` rejects Python >=3.10) | Keep a `numba = ">=0.60"` floor in `pixi.toml`; reproduce Mac resolution on Linux with `uv pip compile --python-platform aarch64-apple-darwin --python-version 3.12` before assuming a transitive-dep fix |
